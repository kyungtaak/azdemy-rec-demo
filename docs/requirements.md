# Azdemy 개인별 교육 추천·상담 서비스

Status: Draft for Demo

## 문서 해석 원칙

- 본 문서는 데모 구현의 요구사항 기준이다.
- 설계 후보는 확정된 기술 결정이 아니다.
- 미확정 사항은 임의로 결정하지 않는다.
- 실제 직원 데이터는 사용하지 않는다.
- 국내 처리 및 Private 연결 요구는 production architecture의
  설계 조건이며, 데모가 해당 요건 충족을 증명하는 것은 아니다.

### 2026-10-20 인프라 실행 승인과 데모 예외

- 현재 Azure CLI 로그인 구독에 신규 전용 RG를 생성하고 Korea Central에 배포합니다.
- 약 2일 유지하며 Bicep what-if 확인 후 실제 배포를 진행하도록 승인받았습니다.
- Foundry Standard Setup과 subnet delegation을 사용합니다. Private 도구 호출을 위한 network injection을 포함합니다.
- Linux Jump host는 공개 IP 없이 구성하고 Bastion Standard의 native tunnel과 SSH SOCKS 접속을 사용합니다. Bastion 관리용 공개 접속은 허용합니다.
- SEC-02·SEC-03의 데모 예외로 Global Standard 모델과 조직 정책에 따른 West US 2 중앙 Log Analytics 저장을 허용합니다. 국내 처리·저장 요건 충족의 증거로 사용하지 않습니다.
- 제안된 GPT-5.6 Terra GlobalStandard 한 개, Search Basic, Cosmos Serverless를 사용합니다. 지원 실패 시 더 비싼 SKU나 key 인증으로 자동 전환하지 않습니다.
- SEC-04·SEC-05의 데이터 서비스 공개 접근 차단과 keyless 인증은 유지합니다. SSH 키는 로컬에만 보관하고 저장소에 기록하지 않습니다.
- 인프라 배포와 교육 API·상담 기능 완성은 구분합니다. 추천 생성·Serving·직원 정보는 Mock이며, 교육 메타데이터도 이용 조건 확인 전에는 합성 데이터를 사용합니다.
- 2일 유지 의도는 자동 삭제 예약이 아닙니다. 만료 태그로 정리 시점을 표시하고, 삭제 시 프로젝트 전용 RG만 대상으로 확인합니다. 기존 중앙 로그·다른 프로젝트 자원은 삭제하지 않습니다.

### 2026-10-21 Fabric 연동 승인과 범위

- 기존 Korea Central `pocfabcap01` F4를 우선 사용합니다. 새 capacity·SKU 상향·유료 overage·Spark autoscale billing은 승인 범위에 없습니다.
- 전용 workspace에만 Private Link와 inbound 공개 접근 차단을 적용합니다. 테넌트 전체 공개 접근 차단이나 기존 PoC workspace의 정책은 변경하지 않습니다.
- Fabric home region은 West US 3입니다. 합성 데모에 한해 해외 tenant 메타데이터를 허용하며, SEC-01~03의 국내 처리·저장 준수 증거로 사용하지 않습니다.
- 기본 Spark ML 콘텐츠 기반 추천 모델과 MLflow 추적을 사용합니다. 품질 개선, 실제 직원 추천 품질의 일반화, MOD-03·04의 시간 분리 평가·품질 입증은 이번 수용 범위에서 제외합니다. 이벤트 시각이나 평가 지표를 임의로 만들지 않습니다.
- 추천 생성은 상담 에이전트 밖에서 실행합니다. 추천 이유는 데이터 근거와 버전별 템플릿으로 생성하며 LLM 설명을 authoritative 이유로 저장하지 않습니다.
- 배치는 수동 실행하고 일반 추천은 최대 3개입니다. 결과의 최대 유효 기간은 실제 생성 시각부터 48시간이며, 동일 실행 재시도로 기간을 연장하지 않습니다.
- 원본 결과는 Lakehouse Delta에, 검증된 API용 복사본은 기존 App Service의 버전별 JSON 영역에 저장합니다. 새 production Serving 서비스는 추가하지 않습니다.
- 완성된 버전만 활성화하며 실패 시 이전 정상 버전을 유지합니다. 이전 버전이 만료되면 cold-start로 전환하거나 만료를 연장하지 않고 `STALE_DATA`를 반환합니다.
- 기존 F4와 Jump host의 재개는 최대 2시간으로 승인됐습니다. 이번 실행이 재개한 자원만 각각 Paused·Deallocated 상태로 복구합니다. 시간 제한은 Azure 청구 hard cap이나 자원 삭제 예약이 아닙니다.
- Workspace inbound 차단과 outbound 격리는 별개입니다. 현재 tenant의 workspace outbound 제어는 비활성화돼 있으며 이를 변경하거나 outbound 격리까지 검증했다고 설명하지 않습니다.
- 최초 2시간 실행 종료 뒤 사용자는 남은 작업을 진행하는 동안 기존 자원을 유지하도록 재개를 별도로 승인했습니다. 기존 제한을 자동 연장한 것으로 기록하지 않으며, 실행 이력과 추가 승인 범위를 구분합니다.
- 수동 추천 Pipeline은 최초 Notebook activity에서 native Spark Job Definition activity로 전환하도록 승인받았습니다. 모델 학습·자동 예약·API 자동 게시는 포함하지 않습니다.
- Native Spark 인증을 위해 전용 workspace identity와 Spark connection, 해당 workspace Contributor를 별도로 승인받았습니다. Foundry account MI·API 역할과 tenant 전역 설정은 변경하지 않습니다.

### 2026-10-22 Azdemy 재배포·공개 승인

- 공개 프로젝트 표시명은 Azdemy, 저장소명은 `azdemy-rec-demo`로 변경합니다. 기존 배포의 자원명·환경변수·저장 경로는 연동 식별자로 유지합니다.
- 기존 Jump host와 F4를 최대 2시간 재개해 API·Prompt Agent·native Spark 배치를 검증하고, 이번에 재개한 자원은 Deallocated·Paused 상태로 복구하도록 승인받았습니다.
- 모델 재학습·새 자원·SKU 변경·권한 확대 없이 기존 승인 모델 버전 1을 사용합니다. 검증된 새 추천 결과의 API 게시는 운영자의 수동 절차로 수행합니다.
- 검증 후 `kyungtaak/azdemy-rec-demo`를 Public 저장소로 게시하고 프로젝트 코드에 MIT License를 적용하도록 승인받았습니다. 기존 제3자 고지는 보존합니다.
- 추가 Foundry 자동 생성 평가 suite는 이번 범위에서 제외합니다. 실제 API·상담 응답의 원본 대조와 로컬 회귀 검사 결과를 구분해 기록합니다.

### 2026-10-22 전용 RG 정리와 다음 배포 이름

- 사용자가 `rg-genius-rec-demo-krc` 전체 삭제를 승인했고, Azure 조회에서 RG가 존재하지 않음을 확인했습니다.
- 공용 Fabric capacity·기존 workspace·중앙 로그·Entra 앱은 삭제하지 않습니다. Foundry·Key Vault soft-delete 항목의 purge도 승인 범위에 없습니다.
- 다음 배포의 RG는 `rg-azdemy-rec-demo-krc`, Bicep 자원명·태그는 `azdemy`를 사용합니다. 앞 절의 기존 자원명 유지 원칙은 과거 검증 기록과 남아 있는 Fabric 항목에 적용합니다.
- API 설정·런타임 환경변수는 `AZDEMY_*`로 함께 변경합니다. API 이름·URL·Foundry endpoint는 새 배포 출력값을 명시적으로 전달하며 이전 hostname을 기본값으로 사용하지 않습니다.
- Fabric workspace·Delta 테이블·모델·게시 저장 경로의 이름 변경은 이번 범위에 없습니다. 새 자원 생성·재배포·권한 설정은 별도 승인과 검증이 필요합니다.

방향은 맞습니다. **여기에 API용 추천 결과 게시, 사용자별 접근 권한, 추천 이력이 없는 사용자 처리, 모델 운영, 국내 처리 범위를 보완하면 Copilot에 전달할 요구사항 초안이 됩니다.**

특히 **Lakehouse에 추천 결과를 저장하는 것과 Azdemy API가 사용자에게 응답하는 것은 별도 단계**입니다. API가 읽을 저장소와 게시 절차를 정의해야 합니다. 아래는 확정 요구와 설계 후보를 구분한 초안입니다.

# Azdemy 개인별 교육 추천·상담 서비스 요구사항 정의서

버전: v0.1 — 협의용 초안

## 1. 목적과 범위

Azdemy 사용자의 직무, 역량, 학습 이력과 교육 콘텐츠를 활용해 개인별 교육 목록을 추천합니다. 사용자는 Azdemy API에서 추천 목록을 조회하고, 상담 에이전트에서 추천 이유와 교육 내용을 확인할 수 있습니다.

추천 모델의 학습과 배치 예측은 Fabric Data Science를 기본으로 검토합니다. 상담 에이전트의 생성형 AI는 Foundry를 사용하되, 국내 데이터 처리·저장과 Private 연결 요건을 만족하는 구성을 선택합니다.

**Azure ML은 초기 필수 구성에 포함하지 않습니다.** 별도 운영 요구가 확인되면 추가 여부를 결정합니다.

## 2. 사용자와 권한

| 사용자 | 주요 기능 |
|---|---|
| 학습자 | 본인 추천 목록 조회, 교육 상담, 추천 피드백 제출 |
| 교육 담당자 | 교육 분류·추천 정책 관리, 허용된 범위의 집계 지표 확인 |
| 모델 운영자 | 모델 학습·평가·승인·배포·롤백 |
| 서비스 운영자 | 파이프라인·API·에이전트 상태 확인, 장애 대응 |

담당자와 운영자가 열람할 수 있는 개인정보 범위는 별도로 정의합니다. 운영 권한이 있다고 해서 직원별 학습 정보 전체를 자동으로 열람할 수 있어서는 안 됩니다.

## 3. 기능 요구사항

### 3.1 개인별 추천 API

| ID | 요구사항 |
|---|---|
| REC-01 | 인증된 사용자는 Azdemy API에서 본인의 추천 교육 목록을 조회할 수 있어야 합니다. |
| REC-02 | 사용자 식별은 인증 정보와 연결해야 합니다. 요청의 사용자 ID만 변경해 다른 직원의 추천을 조회할 수 없어야 합니다. |
| REC-03 | 추천 결과에는 교육 ID, 추천 순위, 추천 생성 시각, 추천 결과 버전과 근거 정보를 포함해야 합니다. 사용자 표시용 교육명·설명·신청 링크는 교육 카탈로그와 연결합니다. |
| REC-04 | 수료 여부, 수강 자격, 선수 과정, 모집 기간, 폐강 여부 등 업무 규칙을 반영해야 합니다. 의무교육은 일반 추천과 구분합니다. |
| REC-05 | 신규 사용자나 학습 이력이 부족한 사용자에게는 직무·역량·교육 정책에 기반한 대체 추천을 제공해야 합니다. 적용한 추천 방식을 구분해 기록합니다. |
| REC-06 | 사용자는 추천의 유용성, 관심 없음 등의 피드백을 남길 수 있어야 합니다. 수집 항목과 활용 범위는 개인정보 정책에 맞춰 정합니다. |

추천 점수는 수강 성공 확률이나 적합도 백분율로 임의 해석하지 않습니다. 점수의 의미와 사용자 노출 여부는 별도로 정합니다.

### 3.2 교육 상담 에이전트

| ID | 요구사항 |
|---|---|
| AGT-01 | 사용자는 자연어로 교육 추천, 추천 이유, 과정 상세 내용과 과정 간 차이를 질문할 수 있어야 합니다. |
| AGT-02 | 에이전트는 권한이 허용된 사용자 정보, 추천 API, 최신 교육 카탈로그와 승인된 교육 콘텐츠를 도구 또는 지식 검색으로 조회해야 합니다. |
| AGT-03 | 개인별 상담에는 필요한 최소한의 사용자 정보만 사용합니다. 다른 직원의 개인정보나 제한된 교육 콘텐츠를 노출해서는 안 됩니다. |
| AGT-04 | 교육 설명에는 확인 가능한 출처를 제시해야 합니다. 근거가 없거나 정보가 충돌하면 확인할 수 없다는 사실을 알려야 합니다. |
| AGT-05 | 모델이 생성한 추천 순위와 상담 과정에서 제안한 대안을 구분해야 합니다. 에이전트가 추천 결과나 추천 이유를 근거 없이 만들어서는 안 됩니다. |
| AGT-06 | 도구 조회 실패, 권한 부족, 추천 결과 없음 상태를 구분해 안내해야 합니다. 실패를 정상 응답으로 숨겨서는 안 됩니다. |

초기 범위는 **조회와 상담**입니다. 수강 신청·취소, 인사 정보 변경처럼 실제 상태를 변경하는 기능은 제외합니다.

교육 콘텐츠에 포함된 문장은 참고 데이터로만 처리합니다. 콘텐츠의 지시문이 에이전트의 권한이나 도구 실행 정책을 바꾸지 못하도록 해야 합니다.

### 3.3 데이터 수집·적재

Landing Zone과 on-premises의 사용자·직무·역량·교육 카탈로그·학습 이력·피드백 데이터를 승인된 연결 경로로 수집해 Fabric Lakehouse에 적재합니다.

| ID | 요구사항 |
|---|---|
| DAT-01 | 데이터 원천별 소유자, 사용 목적, 수집 항목, 갱신 주기와 보존 기간을 정의해야 합니다. |
| DAT-02 | 사용자·교육 식별자를 일관되게 매핑하고, 중복·누락·잘못된 참조를 검사해야 합니다. |
| DAT-03 | 원천 데이터와 학습·서비스용 가공 데이터를 분리합니다. 모델에는 필요한 정보만 사용하고 직접 식별정보는 최소화합니다. |
| DAT-04 | 증분 수집, 재시도와 재실행을 지원해야 합니다. 같은 데이터를 다시 처리해도 중복이나 결과 손상이 발생하지 않아야 합니다. |
| DAT-05 | 원천 데이터의 수정·삭제와 사용자 정보 삭제 요청을 관련 파생 데이터에 반영할 수 있어야 합니다. |

VNet Data Gateway와 Dataflow Gen2 등은 **연결 방식의 후보**입니다. 실제 원천 시스템, 커넥터, Private 구성에서의 지원 여부를 확인한 뒤 확정합니다.

### 3.4 추천 모델 학습·관리

| ID | 요구사항 |
|---|---|
| MOD-01 | Fabric Spark 환경에서 Spark ML 기반 추천 모델을 학습합니다. 알고리즘은 확보된 데이터의 특성과 평가 결과로 결정합니다. |
| MOD-02 | 조회·클릭·수강 신청·수료·평점을 구분합니다. 수료나 클릭을 명시적인 선호 평점과 동일하게 취급하지 않습니다. |
| MOD-03 | 학습·검증 데이터는 시간 순서를 고려해 분리하고 미래 정보 유입을 방지해야 합니다. |
| MOD-04 | 단순 인기 과정·직무별 추천 등 기준 방식과 비교합니다. Top-K 품질 지표와 교육 업무 지표를 함께 평가합니다. |
| MOD-05 | MLflow로 실험, 파라미터, 지표와 모델 버전을 관리합니다. 학습 데이터 버전, 코드 버전과 실행 환경도 추적할 수 있어야 합니다. |
| MOD-06 | 운영 모델은 승인된 버전을 사용합니다. 새 모델이 품질 기준에 미달하면 기존 운영 모델을 유지하고, 이전 버전으로 롤백할 수 있어야 합니다. |

ALS는 초기 후보이지 확정 알고리즘은 아닙니다. 신규 직원과 신규 교육에 사용할 대체 추천 방식도 함께 평가합니다.

### 3.5 배치 추천·서비스 게시

모델 학습과 개인별 추천 생성은 별도 파이프라인으로 구성합니다. 모델을 다시 학습하지 않고도 최신 사용자·교육 데이터를 반영해 추천 결과를 생성할 수 있어야 합니다.

```text
Landing Zone / on-premises
        ↓ 승인된 Private 연결
Fabric Lakehouse
        ├─ 학습 파이프라인 → 평가·승인 → MLflow 모델 등록
        └─ 추천 생성 파이프라인 ← 승인된 모델
                    ↓
             추천 결과 Delta 저장
                    ↓ 검증·게시
          API용 Serving 저장소 / 접근 계층
                    ↓
              Azdemy 추천 API
                    ↑
              Foundry 상담 에이전트
```

| ID | 요구사항 |
|---|---|
| PIP-01 | 개인별 추천 결과를 Lakehouse에 Delta 형식으로 저장하고, 생성 작업·모델·데이터 버전과 연결해야 합니다. |
| PIP-02 | 게시 전 결과 건수, 중복, 교육 유효성, 추천 제외 규칙과 품질을 검사해야 합니다. |
| PIP-03 | 검증된 결과만 서비스에 게시합니다. 사용자가 생성 중인 일부 결과를 조회하지 않도록 게시 버전을 일관되게 전환해야 합니다. |
| PIP-04 | 실패한 작업의 재실행과 이전 게시 버전 복구를 지원해야 합니다. |
| PIP-05 | 마지막 정상 결과를 계속 제공할 수 있는 유효 기간을 정의합니다. 결과가 오래됐으면 이를 표시하거나 정해진 대체 정책을 적용해야 합니다. |

API용 저장소는 응답시간, 동시 요청과 Private 연결 조건에 맞춰 결정합니다. 사용자 요청마다 Spark 작업을 실행하는 구조는 기본안으로 사용하지 않습니다.

## 4. 보안·국내 처리 요구사항

**국내 데이터 처리·저장과 Private 연결은 선택 사항이 아니라 설계 승인 조건입니다.**

| ID | 요구사항 |
|---|---|
| SEC-01 | 원천·가공 데이터, 학습 데이터, 추천 결과, 검색 인덱스, 모델 아티팩트와 백업의 저장·처리 위치를 확인해야 합니다. |
| SEC-02 | 프롬프트, 모델 입력·출력, 임베딩과 대화 이력도 국내 처리·저장 범위에 포함합니다. 로그에 포함된 업무 데이터도 같은 기준을 적용합니다. |
| SEC-03 | 국내 처리 요건을 충족한다고 확인되지 않은 Global·Data Zone deployment와 cross-geo 옵션은 사용하지 않습니다. |
| SEC-04 | 수집, Fabric 작업, 결과 게시, API, 에이전트, 검색·모델 호출의 각 연결 구간에 Private 경로와 공개 접근 차단 정책을 정의해야 합니다. |
| SEC-05 | 서비스 간 인증은 Managed Identity 등 비밀정보를 최소화하는 방식을 우선합니다. 권한은 최소 범위로 부여하고 자격 증명을 코드에 저장하지 않습니다. |
| SEC-06 | 사용자·에이전트·API·검색 계층 모두에서 접근 권한을 적용합니다. 프롬프트만으로 권한을 통제해서는 안 됩니다. |
| SEC-07 | 로그의 개인정보·프롬프트·응답 기록 범위와 보존·삭제 정책을 정의해야 합니다. |

Fabric은 조직의 VNet에 설치하는 제품이 아니라 SaaS입니다. 국내 capacity와 Private Endpoint만으로 전체 요건 충족을 단정하지 않습니다. **테넌트 home region, 메타데이터, 관리·인증 경로와 기능별 제약도 확인해야 합니다.** 지원되지 않는 경로가 발견되면 공개 연결로 우회하지 않고 설계 차단 사유로 보고합니다.

## 5. 운영·수용 기준

다음 기준은 구현 전에 수치와 담당자를 확정해야 합니다.

| 항목 | 확정할 내용 |
|---|---|
| 규모 | 사용자 수, 교육 수, 학습 이력 규모, 동시 API·상담 요청 수 |
| 최신성 | 데이터 수집, 모델 재학습, 추천 생성 주기와 결과 유효 기간 |
| 성능 | 추천 API와 상담 응답시간 목표, 가용성 목표 |
| 품질 | 추천 개수 K, 기준 방식 대비 개선 기준, 상담 근거 정확성 |
| 장애 대응 | 재시도·알림·복구 기준, 이전 결과 유지 정책 |
| 개인정보 | 허용 항목, 동의·이용 근거, 대화·로그 보존 기간 |
| 네트워크 | 조직 내부 사용자 접속 방식, 허용할 인증·관리 의존성 |
| 국내 처리 | 국내 범위의 정확한 정의와 메타데이터·운영 데이터 허용 기준 |

수용 시험에는 정상 조회뿐 아니라 다른 사용자 정보 접근 차단, 신규 사용자 대체 추천, 폐강·권한 변경 반영, 파이프라인 실패·재실행, 모델 롤백과 공개 접근 차단을 포함합니다.

## 6. VS Code Copilot 구현 지침

이 정의서를 기준으로 구현하되, 미확정 사항은 설정값 또는 명시적인 TODO로 남깁니다. 임의로 제품·리전·모델·성능 수치를 확정하지 않습니다.

1. 추천 API, 상담 에이전트, 데이터 수집, 모델 학습, 추천 생성·게시의 책임을 분리합니다.
2. API 계약과 데이터 스키마를 먼저 정의하고, 사용자·교육·추천 결과·모델 버전의 연결 관계를 명시합니다.
3. 로컬 개발은 합성 데이터와 mock 도구로 진행합니다. 실제 직원 정보나 자격 증명을 저장소에 포함하지 않습니다.
4. 개발용 mock과 운영 연결을 명확히 구분합니다. 인증 생략이나 공개 연결이 운영 설정으로 넘어가지 않도록 합니다.
5. 서비스·리전·Private 기능의 지원 여부를 추측하지 않습니다. 확인이 필요한 항목은 근거와 함께 설계 차단 사항으로 기록합니다.
6. 오류를 빈 추천 목록이나 성공 응답으로 숨기지 않습니다. 결과 없음, 권한 부족, 데이터 지연과 시스템 오류를 구분합니다.
7. Azure ML, 실시간 재학습, 수강 신청·취소 기능은 별도 승인 없이 초기 범위에 추가하지 않습니다.
